# Native-scoped publisher observation

This opt-in mode is a finite diagnostic, with `qualification_admissible=false` and `capacity_accepted=false`. It does not establish capacity acceptance. The default selector is `legacy`. Existing admission, topology, profiler and formal acceptance protections remain in place; `worker_metrics.py` is unchanged.

Select `publisher_observation=true`, `publisher_observation_mode=native-scoped`, `diagnostic_profile=false`, `runtime_diagnostics=false`, `writer_topology=writers-6`, and `consumer_topology=notification-dual`. The workflow rejects every other combination before services start. The publisher probe accepts only the closed `legacy|native-scoped` selector and bounds its existing workload inputs. It uses the original smoke harness, seed, six writers, two notification consumers, journal files, native clients, service resources, endpoints, 900-second drain, metrics sampling and scoped cleanup. No SQL sampler, function profiler, server instrumentation or new workload is enabled. A prospective diagnostic must use the existing 3,000 events, 50 events/second and 60-second duration; runner and resource declarations must match its frozen input manifest.

The new launcher uses the command's existing global `PublisherBudgetAdmission` object. It never constructs or recaptures a policy. The command calls the original `plain` guard once, with its original arguments, and returns that original result to the original batch controller. A clock surrounds that call; guard-result bookkeeping happens after the measured scope. Native-selector bookkeeping likewise happens after its clock scope. Scope entry/exit and record allocation contribute some instrumentation CPU within the span, so it is not an exact bare-call measurement. Observed results gate diagnostic hooks only; they never decide business admission. The original readiness, function, binding, field, namespace, MRO, session, owner, lease, deadline, budget, receipt, acknowledgement and writeback checks execute on their original paths.

The source clocks distinguish guard call, native claim eligibility, complete claim call, envelope, lease check, send and fenced publication writeback. Only after both the real guard and the real native claim selection returned `True` does the claim scope temporarily install an application execute wrapper, an `OutboxEvent.from_db` callback and a physical application commit callback. Each invokes the original exactly once with unchanged arguments, return value and exception. No hook is installed on the dedicated owner connection. Fixed scope entry installs nothing; installation happens inside its entered body, with owned restoration intent recorded before native mutations. Cleanup attempts execute, commit and model restoration independently, followed by one bounded native removal of still-owned bindings after a control. It never removes a foreign replacement. It rethrows the first cleanup control only after all phases, preserving an existing business primary. The captured native deadline exception is never swallowed as an ordinary diagnostic fault. These hooks restore the original absence of model and instance bindings, and remove the authored wrapper before the next record/session recheck. Per-attempt restored status uses install/restore/failure deltas as well as depth. Lease-check and writeback scopes temporarily observe their existing driver executes without changing SQL, parameters or call counts. There is no extra SQL, polling, flushing, retry, producer batching or workload.

The native producer is never replaced. At the existing `events.send` produce callsite, a wrapper taps the original source lambda callback, preserving its native list closure and invoking the original callback once. The timestamp is sampled after that callback. Unsupported callback shapes remain the original callback and are counted as unavailable; unknown and failed acknowledgements cannot qualify a complete observation. Original `produce`, queue-budget polling, flush, acknowledgement validation and publication fencing retain their behavior.

The fixed observer supports only its authored classes and methods. Captured native types and dictionary methods first validate exact dictionary/string shapes before reading names. It then checks the fixed class namespaces, MRO, function identity/code/defaults/closure cells, native builtins and native clock/thread/process bindings. There are no contextlib constructors, generic callback registry, decision cache or native-ID token cache. Unknown shadows are refused without calling them. Instance callbacks cannot override an admitted method. The inactive path returns directly to the original business call; inert helper lookup and branching still add some Python work, so this is not a claim of zero disabled-mode overhead. The original non-atomic scope of concurrent monkeypatch protection remains; this diagnostic does not claim atomic safety against a mutation racing a checked call.

Each publisher is a single observed process/thread, with at most 4,096 sampled attempts and 131,072 records. Rows contain only bounded stage names, event IDs, parent IDs, native timestamps, outcome and sanitized exception types. No SQL, parameters, payloads, broker messages or credentials are captured. Rows are grouped in one pass at close. Attempt and record denominators, dropped rows, hook installs/restores, clock failures, late/nonowner/unavailable callbacks and incomplete boundaries are explicit. Missing or fallback boundaries are never filled by estimates. Only a returned, original-guard-true/native-claim-true attempt with all required complete boundaries, successful single ACK for a published event and restored hooks is complete. Empty claims have their own denominator and require no ACK. An incomplete observation remains `OBSERVED_PARTIAL`; every overall result remains diagnostic only.

Clock-read thread CPU is reported as a lower bound on instrumentation overhead. It excludes observer proof, allocation, wrapper dispatch and serialization, so it must not be subtracted as a full overhead correction. Nested times overlap and must not be added. Claim execute excludes fetching; `from_db` excludes converters outside that method. Publication execute includes driver autocommit, so a separate final physical writeback commit is unavailable. Client epoch timestamps and PostgreSQL commit times are uncalibrated.

Two hard measurement limits remain:

1. Native candidate selection and lease update use one existing atomic CTE execute. Their server-side causal shares are **UNKNOWN** and cannot be separated by these client clocks.
2. The clock around `plain` measures inclusive elapsed time and inclusive own-thread call CPU, including callees. Exclusive function-own CPU is **UNAVAILABLE** on the protected six-writer/dual-consumer topology because profilers remain disabled.

The prospective tests cover real PostgreSQL original-policy admission and claim/commit/restoration, callback invocation and controls, source clock denominators, zero unknown-hook dispatch and closed CLI declarations. Prepared test source is not execution evidence. A future chosen run must preserve raw observation, journals, manifests, checksums, source hashes, exceptions and scoped cleanup evidence even when incomplete. It cannot replace the separate formal capacity gate.
